Vulnerability Research & Disclosure

Original Discovery: CVE-2026-115449

Security research conducted by Manifold Operations founder Piyusha Akash (0x3xp) led to the identification and upstream patching of a hypervisor NAT isolation vulnerability in libslirp.

CVE-2026-115449 / libslirp
Target: freedesktop.org / libslirp (QEMU Network Stack) · Disclosed: Oct 2026 · Reporter: Piyusha Akash
CWE-200 Info Disclosure Upstream Merged CVSS:3.1 3.5 (Low)

"Red Hat would like to thank Piyusha Akash for reporting this issue."

Official Red Hat Product Security Advisory · Bugzilla RHBZ#2558916

Vulnerability Overview & Impact

During source code auditing of libslirp—the user-mode TCP/IP networking stack powering QEMU, VirtualBox, and hypervisors worldwide—a flaw was identified in the handling of ICMP echo requests.

When the fallback ICMP socket path is engaged (due to restricted ping_group_range) and an unprivileged guest pings a non-existent host on the hypervisor LAN, the echo reply length is not updated to match actual data received from the host.

This length mismatch causes trailing uninitialized packet buffer slices containing the host hypervisor's real physical IP address to be leaked into the guest echo reply, breaking the NAT containment boundary that user-mode networking is designed to enforce.

7 security, memory safety, resource management, and concurrency fixes authored by Piyusha Akash merged into production freedesktop.org / libslirp—the virtualization network stack in QEMU.

[CVE-2026-115449] Echo reply length desynchronization in icmp_receive() & icmp6_receive()

CVE-2026-115449 · Merged

Length field desynchronization in ICMP echo replies when raw socket fallback path is taken leaks host hypervisor LAN IP address to guest virtual machine, breaking user-mode NAT containment.

GitLab Commit 262c9be ↗ Work Item #105 ↗ Red Hat Advisory ↗ View Advisory Deep Dive →

Memory leak of tftp_server_name in slirp_cleanup()

Merged

tftp_server_name was heap-allocated during initialization but never freed in the cleanup path slirp_cleanup(), causing a persistent memory leak on every virtual machine teardown in QEMU.

GitLab Commit fe2501e ↗ Work Item #99 ↗

Buffer underflow in tftp_handle_rrq() when handling empty filename

Merged

When a TFTP read request (RRQ) was received with an empty filename, tftp_handle_rrq() performed pointer arithmetic that resulted in a buffer underflow, reading out-of-bounds memory before the start of the buffer.

GitLab Commit 9fd2fa6 ↗ Work Item #100 ↗

Protocol type mismatch in icmp6_receive(): IPv4 ICMP_UNREACH emitted as ICMPv6

Merged

An IPv4 ICMP_UNREACH error was incorrectly emitted using the ICMPv6 send path. This protocol mismatch caused malformed packets to be transmitted, breaking network error signaling.

GitLab Commit 0bda8ef ↗ Work Item #101 ↗

Double socket descriptor leak in fork_exec() on argument parsing failure

Merged

Two connected socket descriptors allocated via slirp_socketpair_with_oob() were never closed if argument parsing failed prior to the fork, risking file descriptor exhaustion and denial of service.

GitLab Commit 8bb18d3 ↗ Work Item #102 ↗

Socket heap memory & buffer leak in slirp_state_load() on deserialization failure

Merged

If deserialization of a socket failed partway through in slirp_state_load(), allocated socket structures and buffers were not freed before returning, resulting in heap leaks during failed VM state restore operations.

GitLab Commit 7e571d1 ↗ Work Item #103 ↗

Non-reentrant static variable in tcp_emu() corrupts protocol parser across sessions

Merged

A static local variable was used to track parser state. Concurrent or interleaved network sessions corrupted each other's protocol state, causing silent packet parsing failures across multi-instance virtual hypervisors.
