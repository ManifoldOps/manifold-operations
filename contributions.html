CVE-2026-115449: Host IP Leak in libslirp

Libslirp: ICMP Echo Reply Length Desynchronization Leaks Host IP to Guest

freedesktop.org / libslirp · Oct 2026 · C / Protocol Security

CVE-2026-115449 Merged CVSS:3.1 3.5

During source code auditing of libslirp, a flaw was discovered in how ICMP echo requests are handled in user-mode networking. When the fallback ICMP socket path is engaged, the reply packet length field is not updated to match the actual data received from the host operating system.

Under specific conditions, this length desynchronization causes uninitialized packet buffer contents containing the host's real IP address to be returned in the echo reply packet to the guest virtual machine. This breaks the network address translation (NAT) isolation boundary that user-mode networking is designed to enforce, leaking host network topology to unprivileged virtual machines.

Upstream libslirp Commits

Complete catalog of 7 upstream security, memory safety, and protocol stability patches authored by Piyusha Akash and merged into freedesktop.org / libslirp.

PATCH 01 · SECURITY / CVE

Echo reply length desynchronization in icmp_receive() and icmp6_receive()

CVE-2026-115449

In both icmp_receive() and icmp6_receive(), the length field of echo reply packets is not correctly synchronized with actual received payload size. Under specific conditions where the normal ICMP socket is unavailable, this causes trailing uninitialized buffer bytes containing the host's actual IP to be emitted to the guest, breaking NAT isolation.

PATCH 02 · MEMORY SAFETY

Memory leak of tftp_server_name in slirp_cleanup()

Merged

tftp_server_name is heap-allocated during initialization but was never freed in the cleanup path slirp_cleanup(), causing a persistent memory leak on every virtual instance teardown in QEMU and other consumers of libslirp.

PATCH 03 · BUFFER SAFETY

Buffer underflow in tftp_handle_rrq() when handling empty filename

Merged

When a TFTP read request (RRQ) is received with an empty filename, tftp_handle_rrq() performed pointer arithmetic that resulted in a buffer underflow—reading memory before the start of the allocated buffer. This can cause undefined behavior and potential memory exposure.

GitLab Commit 9fd2fa6 ↗ Work Item #100 ↗
PATCH 04 · PROTOCOL CORRECTNESS

Protocol type mismatch in icmp6_receive(): IPv4 ICMP_UNREACH emitted as ICMPv6

Merged

In icmp6_receive(), an IPv4 ICMP_UNREACH error was incorrectly emitted using the ICMPv6 send path. This protocol type mismatch caused malformed packets to be constructed and sent, breaking network error signaling for IPv4 unreachable conditions handled through the IPv6 receive path.

GitLab Commit 0bda8ef ↗ Work Item #101 ↗
PATCH 05 · RESOURCE MANAGEMENT

Double socket descriptor leak in fork_exec() on argument parsing failure

Merged

In fork_exec(), two connected socket descriptors allocated via slirp_socketpair_with_oob() were never closed if argument parsing failed prior to the fork. Repeated failures in callers would exhaust the host process file descriptor table, resulting in denial of service for guest networking.

GitLab Commit 8bb18d3 ↗ Work Item #102 ↗
PATCH 06 · STATE PERSISTENCE / LEAKS

Socket heap memory & buffer leak in slirp_state_load() on deserialization failure

Merged

In slirp_state_load(), if deserialization or validation of a socket failed partway through, the already-allocated socket structure and its associated send/receive buffers were not freed before returning an error. This resulted in heap memory and buffer leaks on failed state restore operations.

GitLab Commit 7e571d1 ↗ Work Item #103 ↗
PATCH 07 · CONCURRENCY / REENTRANCY

Non-reentrant static variable in tcp_emu() corrupts protocol parser across sessions

Merged

tcp_emu() used a static local variable to maintain parser state across calls. Because static local variables are shared across all call sites in a process, concurrent or interleaved sessions corrupted each other's protocol parser state—causing silent protocol parsing failures in multi-instance libslirp environments.

About libslirp & Upstream Systems Security

libslirp is the user-mode TCP/IP networking stack used by QEMU, VirtualBox, and major virtualization and emulation platforms. It implements a complete network stack in user space, translating guest network traffic without requiring elevated host operating system privileges. Security and memory safety issues in libslirp directly affect host-guest containment and hypervisor reliability.

All contributions documented above were identified through manual source-level code review by Piyusha Akash, reported upstream with reproduction context and fix proposals, and subsequently merged into the main project repository.
